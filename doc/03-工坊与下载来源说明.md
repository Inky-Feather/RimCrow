# 工坊与下载来源说明

这份文档说明 RimCrow 里几种常见 Mod 获取方式：Steam 订阅、SteamCMD 下载、合集导入、Git 仓库订阅和 zip 直链。

先记住一个区别：

- Steam 订阅：由 Steam 客户端管理，管理与加载 Steam Workshop 创意工坊的模组。
- SteamCMD 下载：通过 SteamCMD 将创意工坊模组下载到 RimCrow 的管理器模组库，绕过 Steam 客户端限制。
- Git / 直链：适合不在创意工坊的以仓库发布的 Mod。

## 先按场景选择

### 希望 Steam 自动更新管理模组

优先用 Steam 订阅。

适合：

- Steam 正版玩家。
- 希望 Steam 自动更新工坊 Mod。
- 不想手动管理下载目录。

设置建议：

- 优先使用 Steam 启动：开启。
- 使用创意工坊 Mod：关闭。
- 工坊订阅、更新和卸载交给 Steam。

### 希望手动管理模组的更新

用管理器的 SteamCMD 下载模组到 RimCrow 管理器下载模组路径。

适合：

- 想手动管理工坊 Mod 的更新变动。
- 不想依赖当前 Steam 订阅列表。
- 想和 Git / 直链 来源一起集中管理。

下载后需要开启“使用管理器模组”，游戏才会通过链接方式读取这些 Mod。

### 工坊合集导入

在合集订阅管理中导入目标合集链接或工坊id。

适合：

- 别人给了 Steam 合集链接或合集 ID。
- 你想快速查看合集包含哪些 Mod。
- 希望随时查看合集内容是否更新。
- 你想补齐缺失项，再决定是否套用顺序。

### 模组只在 Git 仓库发布

用 Git 仓库订阅。

适合：

- Mod 没有上传创意工坊。
- 作者在 GitHub、GitLab 或 GitGud 发布源码。
- 作者通过 Release 发布打包版本。

## 库存枢纽页面

点击“库存枢纽”会进入工作区，顶部有几个主要页面：

- 全库数据管理：查看工坊、本地和管理器库库存。
- 创意工坊检索：搜索工坊项目，查看详情、依赖、截图和作者信息。
- 合集订阅管理：导入 Steam 合集，查看合集内项目和缺失状态。
- Git 仓库订阅：添加 Git / 直链 来源，查看订阅状态和部署记录。

## Steam 订阅

Steam 订阅会把工坊项目加入你的 Steam 订阅列表。下载、更新和卸载主要由 Steam 客户端负责。

适合：

- 正常使用 Steam 版 RimWorld。
- 希望跟随工坊自动更新。
- 希望保持官方行为。

注意：

- 需要 Steam 已登录并能访问工坊。
- 订阅后 Steam 不一定立刻下载完成。
- 取消订阅不等于 RimCrow 一定马上看不到文件，仍要看 Steam 是否已清理本地文件。

## SteamCMD 下载

SteamCMD 是独立下载工具。RimCrow 可以用它把工坊项目下载到管理器模组库。

适合：

- 想独立保存 Mod 文件。
- 想让管理器库集中管理下载内容。
- 想绕开 Steam 客户端订阅列表做下载。

注意：

- SteamCMD 目录不要包含中文。
- 下载目录建议在 NTFS 磁盘。
- SteamCMD 下载通常不等于 Steam 客户端订阅。
- 下载后需要扫描，列表才会更新。
- 使用这些 Mod 前，当前环境要开启“使用管理器模组”。

SteamCMD 路径和管理器模组路径的关系见 [环境管理与路径说明](./02-环境管理与路径说明.md)。

## 创意工坊检索

创意工坊检索可以按 Mod 名、包名或工坊 ID 搜索。

结果区通常会显示：

- Mod 名称和工坊 ID。
- 包名、作者、版本信息。
- 订阅状态。
- 简介、依赖、截图和相关项目。

常用动作：

- 订阅到 Steam。
- 取消订阅。
- 下载到管理器。
- 打开网页工坊页面。
- 查看依赖、同作者项目或相关项目。

增强模式可以获取更完整的工坊信息；关闭时会更多依赖本地缓存和公开接口，结果可能不完整。

## 合集订阅管理

合集页适合处理别人分享的 Steam 工坊合集。

推荐流程：

1. 粘贴合集 URL 或输入合集 ID。
2. 选择导入的合集记录。
3. 查看包含哪些 Mod。
4. 检查哪些已订阅、已安装或缺失。
5. 批量订阅或下载缺失项。
6. 最后再决定是否把合集顺序应用到当前列表。

不要一导入就直接覆盖当前启用列表。先看差异和缺失项更稳。

## Git 仓库订阅

Git 仓库订阅适合没有上传工坊，或作者主要在代码托管平台发布的 Mod。

支持常见公开仓库：

- GitHub
- GitLab
- GitGud

也支持部分 zip 直链来源。

### Source 模式

Source 模式会获取源码分支内容。

适合：

- 作者没有发布 Release。
- 你想跟进测试版或最新提交。
- 仓库结构本身就是可用 Mod。

风险：

- 源码分支可能不稳定。
- 有些仓库需要构建后才是可用 Mod。

### Release 模式

Release 模式会获取作者发布的打包版本。

适合：

- 作者有正式 Release。
- 你想使用更稳定的版本。
- 不想处理源码目录结构。

如果仓库没有 Release，这个模式不可用。

### zip 直链

zip 直链适合推荐清单或第三方来源里的打包文件。

注意：

- zip 来源依赖链接稳定性。
- 链接失效后需要换来源。
- 下载后仍要扫描和确认 Mod 结构是否正确。


## 网络访问和下载加速（仅限中国大陆网络环境）

入口：**设置 → 网络连接**。网络正常时不必调整；遇到访问慢或失败时，按问题选择对应选项，不需要全部开启。

### 按问题选择设置

| 遇到的问题 | 可以尝试 | 需要注意 |
| --- | --- | --- |
| GitHub 项目页面、文件或下载包访问慢、打不开 | GitHub 镜像源 | 只帮助访问节点支持的 GitHub 内容，不改善 Steam 等其他网站 |
| 多个外部网站无法访问，且你已有可用的代理服务 | 启用代理服务 | 按代理工具提供的信息填写协议、主机地址和端口；没有可用服务时，单独打开开关无效 |
| 提示找不到服务器或域名解析失败 | 动态 Hosts | 只帮助查找网站地址，不能修复服务器故障或代理连接失败 |

### GitHub 镜像怎样选

在“GitHub 镜像源”的“镜像节点”中选择：

- **GitHub 直连**：不用镜像，访问 GitHub 原地址；如果配置了代理，仍会遵循代理设置。
- **具体节点**：优先使用所选节点；节点不支持对应内容或访问失败时，会尝试 GitHub 原地址。
- **自动选择镜像**：先打开“启用动态镜像节点”，等待获取和检测，再选择此项，让软件从当前可用节点中选择。

需要自定义节点时，使用选择器旁的新增、编辑或删除按钮。只使用可信节点；带账号凭据的请求和私有资源不会交给公共镜像。

软件自身更新采用独立策略：先访问 GitHub 原地址，失败后自动尝试内置的 `gh-proxy.org`，不跟随这里选择的镜像节点；即使选择“GitHub 直连”，软件更新仍保留该备用路径。它只读取公开发布信息和安装包，不向公共镜像发送账号凭据，且仍遵循应用代理设置。

### 软件更新怎样处理多个下载来源

在“关于项目”中点击“检查更新”。软件会汇总多个发布平台的结果，只展示最高适用版本的一份更新说明；展开“来源详情”可查看各站的检查结果。部分来源失败时仍可使用已发现的更新，未发现更新也不代表无法访问的来源一定没有新版本。

点击“下载更新”后可在任务栏查看进度，失败时自动尝试同版本备用地址。下载完成后可以稍后安装；继续安装时需依次确认安装和重启，任意一次取消都不会执行安装。稍后可从“关于项目”的“查看更新”重新打开。

### 代理开关影响哪些功能

- **启用代理服务**是应用代理总开关，用于普通查询、文件下载和更新检查等请求；镜像地址与原地址都会遵循此设置。“不走代理的域名”用于排除特定网站。
- **为 AI 请求使用代理**单独控制 AI 是否使用这里配置的代理，需要同时打开总开关；关闭 AI 开关不影响普通请求。
- **为 SteamCMD 使用代理**需要同时打开总开关，但不保证能解决 SteamCMD 的所有连接或下载问题。
- 关闭总开关只是不再使用这里配置的代理，**不等于强制直连**；外部代理环境仍可能生效。这里的设置不修改其他程序的代理，也不保证控制 Steam 客户端或内置浏览器的连接。
- 软件更新使用蓝奏云备用来源时，会直接连接，不使用这里配置的代理或环境代理。

### 动态 Hosts 怎样使用

1. 打开“动态 Hosts”，检查“Hosts 来源”中已启用的地址；通常无需修改，确需添加时只使用可信来源。
2. 等待获取结果。显示“Hosts 已获取，保存设置后生效”时，点击底部的“应用并保存配置”；获取失败时可检查网络和来源后点击“重新获取”，已有映射会保留。
3. 需要定期更新时，开启“自动更新动态 Hosts”并设置更新间隔。它会在软件启动时检查是否已到更新时间。

Hosts 不限于 GitHub 或 Steam，能帮助访问哪些网站取决于来源包含哪些域名。明确知道正确 IP 时，也可填写“自定义 Hosts 映射”；同一域名以手动填写的映射为准。

默认只影响软件自身的后台请求，不自动应用到内置浏览器。**“将 Hosts 映射应用到系统”会修改系统文件，并影响其他程序，可能需要管理员权限，通常无需开启。**确需使用时，保存后按提示确认是否成功，再刷新或重开浏览器；通过代理访问时，这些映射不一定生效。

### 检测、保存与排查

调整后可点击右上角“检测访问”，查看当前表单配置下各站点的结果；将鼠标停在结果上可查看连接详情。**检测不会保存或应用表单中的配置，动态 Hosts 的获取预览也不会更改当前生效的映射。**要验证刚获取的动态映射，请先保存，再检测。

- 检测延时不是大文件下载速度；一个站点检测成功，也不代表它的所有页面和文件都能访问，更不代表 AI 或 SteamCMD 已通过检测。
- 确认可用后点击“应用并保存配置”；不想保留本次设置时点击“放弃修改”。
- 工坊浏览器打不开时，先确认外部网络能访问 Steam 工坊，再检查浏览器使用的网络环境；不要仅凭后台检测成功判断浏览器也能访问。页面能打开但图片缺失时，还需确认图片来源也能访问。
- 仍然失败时，记录失败的功能和提示，按 [日志排错与 AI 诊断说明](./08-日志排错与AI诊断说明.md) 查看日志，再有针对性地调整，不必反复叠加镜像、代理和 Hosts。

## 更新检查

RimCrow 可以显示工坊、SteamCMD 和 Git 来源的状态变化，但不同来源的更新时间口径不同。

常见状态：

- 已安装：本地能找到文件。
- 已订阅：Steam 订阅列表里存在。
- 有变动：发生了明显文件变动或更新的模组。
- 有更新：远端或记录显示可能有新版本。
- 已删除：可能在游戏中或其它第三方因素导致的模组缺失或删除。
- 缺失：记录存在，但本地没有有效文件，通常仍处于订阅状态，可能为工坊下架或 Steam 同步等原因导致的文件意外删除。

遇到状态不一致时，先重新扫描，再检查来源本身是否可访问，然后进行相应的处理操作，如：重新订阅、重新下载等。

## 推荐用法

### 普通 Steam 玩家

- 工坊 Mod 用 Steam 订阅。
- 用 Steam 启动游戏。
- 不把 Steam 工坊目录当成管理器库。

### 整合包爱好者

- 用合集页导入别人分享的合集。
- 用备份导入导出管理加载顺序。
- 用 SteamCMD 或 Git 订阅补充非 Steam 来源。
- 保留每次大改前的备份。

### 测试新 Mod

- 先下载到管理器库或单独环境。
- 扫描后只启用少量相关 Mod。
- 自动排序并保存。
- 进入游戏测试，确认稳定后再并入常用环境。

## 常见问题

### 订阅了但列表里没有

Steam 可能还没下载完成。先等 Steam 下载结束，再重新扫描。

### SteamCMD 下载成功但游戏没加载

检查当前环境是否开启“使用管理器模组”，并确认启动前链接同步成功。

### Git 仓库订阅后不能用

优先检查模组文件是否成功下载，可能因网络原因导致下载失败。另外可能是仓库源码不是直接可用的 Mod，或需要 Release 打包版本。优先查看仓库 README 和文件结构。

### 工坊项目显示失效

可能是项目下架、隐藏、地区访问异常，或本地缓存过旧。先刷新和重新扫描，再尝试打开工坊页面确认。

## 注意事项

- 不要把 Steam 官方工坊目录和管理器下载模组路径混用。
- 订阅、下载、部署是不同动作，完成一个不代表另一个已经完成。
- 更新前后建议扫描，避免列表使用旧状态。
- 删除或取消订阅前先确认来源，避免删错副本。
