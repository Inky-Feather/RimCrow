# Texture Optimization

> **Translation notice:** This English document was generated with AI assistance from the Chinese source doc. Some descriptions may be inaccurate or not fully aligned with the current UI. Corrections and improvement suggestions are welcome.

This guide explains RimCrow texture optimization options for normal players: what they do, when to use them, expected effects, and risks.

## Quick Recommendation

If you want a safe way to reduce texture loading pressure in a large mod list, start with:

- Range: process new textures only, or process all textures when refreshing settings.
- Output format: DDS.
- Scale ratio: 50% or 60%.
- Minimum clarity: 128.
- Generate mipmaps: on.

If you care about image quality, start with DDS and no scaling. If VRAM is tight or the mod list is very large, lower the scale gradually to 75%, 60%, or 50%. Do not start with 20% or 25% unless you can accept visibly blurrier textures.

## What Texture Optimization Does

RimWorld mods commonly use PNG textures. PNG is good for storage and usually small on disk, but the game must decode it before the GPU can use it. Texture optimization prepares DDS or DDS.ZSTD files in advance, and can resize textures first when needed.

Simple view:

- PNG is the original texture. It is often small on disk but needs runtime decoding.
- DDS is closer to a GPU-ready texture format and is easier for the game to read.
- DDS.ZSTD compresses DDS again to save disk space.
- Scaling lowers texture resolution, mainly to reduce VRAM usage.

RimCrow does not modify the original PNG. It generates output files beside the originals, so you can clean or regenerate them later.

## Common Plans

| Plan | What It Does | Main Benefit | Main Cost | Best For |
| --- | --- | --- | --- | --- |
| Keep PNG | No processing | No extra files | Game still reads and decodes PNG | Small lists or no texture issue |
| Full-size DDS | PNG to DDS without scaling | Less runtime decoding pressure | DDS usually uses more disk space | Safe optimization without quality loss |
| Full-size ZSTD | DDS then `.dds.zstd` | Saves disk space compared with DDS | Needs Image Opt, still decompresses before use | Tight disk space with Image Opt |
| Scaled DDS | Resize then generate DDS | Lower VRAM use and texture size | Lower image quality | Large lists or VRAM pressure |
| Scaled ZSTD | Resize then DDS.ZSTD | Saves VRAM and disk | Needs Image Opt, slower generation | Many mods with tight VRAM and disk |

## Game Native Texture Compression

RimWorld has its own texture compression setting, named `textureCompression`. This is not the same as RimCrow generating DDS, ZSTD, or scaled textures.

Simple view:

- RimCrow optimization prepares files in advance.
- Game native texture compression tries to compress textures at runtime.

They are not mutually exclusive. Even after generating DDS, the game may still pack textures into atlases and compress them according to this setting. In large mod lists, native texture compression may still noticeably affect VRAM usage.

### Suggested Choice

Most users should keep it enabled, especially when:

- You have many mods.
- VRAM is limited.
- In-game texture loading is slow or VRAM is near the limit.
- You use scaled DDS or scaled ZSTD to save VRAM.

You can try disabling it when:

- VRAM is enough.
- You care more about fine visual details.
- You want to compare load time.
- You suspect compression causes edge, gradient, or transparency problems.

### Benefits

- Usually lowers runtime VRAM usage.
- Makes large mod setups less likely to run out of VRAM.
- Also affects texture atlases generated by the game.
- Can be used together with DDS, ZSTD, and scaling.

### Costs

- Startup may do extra compression work, so load time may not always be shorter.
- Compression is lossy. Details, gradients, and transparent edges may look slightly worse.
- Restart the game after changing the setting.

If unsure, keep it enabled. Try disabling it only when VRAM is enough, image quality matters more, or you are testing.

## Processing Range

| Option | Meaning | Best For |
| --- | --- | --- |
| Process all textures | Regenerate all outputs in the selected range | Refresh after changing format, scale, or mipmaps |
| Process new textures only | Keep existing outputs and fill missing ones | Daily use after adding a few mods |
| Process scalable images only | Mainly overwrite images that need scaling | Reducing repeated work during scaling |

If you are unsure whether settings are consistent, process all textures. For daily small additions, incremental processing saves time.

## DDS

DDS is the most common and stable output format. RimWorld 1.6 can read DDS natively. Older versions usually need a mod such as Graphics Settings+.

Benefits:

- Less PNG decoding during game loading.
- May reduce texture-related stutter and VRAM risk in large lists.
- Usually no quality loss when not scaling.

Risks:

- DDS files usually use more disk space than PNG.
- First generation takes time. More mods and more textures mean longer processing.
- Older game versions or missing DDS support may make the game keep using PNG.

## ZSTD

ZSTD output is `.dds.zstd`. It is not a new direct replacement for DDS. It compresses DDS further to save disk space.

Benefits:

- Uses less disk space than normal DDS.
- With scaling, it can reduce both disk use and VRAM pressure.

Risks:

- Needs Image Opt to be read by the game.
- Without Image Opt installed and enabled, files may be generated but unused.
- Reading requires decompression, so actual load behavior depends on hardware, disk, and Image Opt.

## Scale Ratio

Scale ratio decides how small the image becomes. Lower ratio saves more VRAM but lowers quality more.

Common choices:

- No scaling: safest, no clarity loss, mainly improves reading through DDS.
- 80% / 75%: light optimization with small quality impact.
- 60% / 50%: balanced choice for most large mod lists.
- 40%: more aggressive, for clear VRAM pressure.
- 25% / 20%: very aggressive, saves resources but can look blurry.

Start with 60% or 50%. If textures look too blurry in game, raise the ratio and regenerate.

## Minimum Clarity

Minimum clarity prevents images from becoming too small.

For example, with 128, scaling tries not to make the shortest side smaller than 128. This protects small icons, decorations, and UI textures.

Simple view:

- Scale ratio says how much you want to shrink.
- Minimum clarity says where shrinking should stop.

If unsure, keep 128.

## Auto Fallback

Some images should not use the selected scale, usually because they would fall below the minimum clarity. RimCrow can fall back to a safer scale, or keep original size when needed.

Fallback is not an error. It means forcing the selected ratio could make the image too small or unsuitable.

When results show "fallback 50%" or "fallback 75%", those images used a safer ratio instead of your lowest selected ratio.

## No Scaling, Mask Textures, And Out Of Range

"No scaling" results usually include:

- No scaling: kept original size due to settings or image conditions.
- Mask texture no scaling: files such as `*_m.png` generate full-size DDS but are not scaled.
- Out of range no scaling: image is too small or too large for current scaling rules, so original size is kept.

Mask textures are more like data images for rendering. Scaling them may cause edge, channel, or display problems, so full-size DDS is safer.

## Mipmaps

Mipmaps are smaller versions of a texture used when viewing from distance.

When enabled:

- Distant textures may look smoother.
- Flickering and aliasing may be reduced.
- File size and generation time increase a little.

When disabled:

- Output may be smaller and faster to generate.
- Distant textures may shimmer more.

Usually keep mipmaps enabled.

## Clean Generated Textures

Cleanup deletes generated DDS or DDS.ZSTD files.

Common uses:

- Remove old format after changing output format.
- Delete old outputs after changing scaling strategy, then regenerate.
- Clean leftovers after uninstalling mods.
- Delete generated outputs whose source PNG no longer exists.

Before cleanup, confirm the target range and output format so you do not delete results you still want.

## Why Load Time May Not Always Improve

Texture optimization can reduce texture reading, decoding, and GPU upload pressure, but game startup time depends on many things:

- System file cache.
- Disk speed and background processes.
- Mod XML, Defs, and PatchOperation parsing.
- C# mod initialization.
- Audio, preview images, shaders, and other resources.
- First launch and repeated launch states.

Use load time as a reference, not the only standard. Better signals:

- Less texture stutter after entering the game.
- Lower VRAM risk.
- Large mod lists feel more stable.
- Disk usage is still acceptable.

## Why VRAM Estimate Differs From Real Usage

RimCrow's VRAM estimate helps compare plans. It is not the exact number you will see in the game process.

Reasons:

- The game and GPU driver manage resources and cache differently.
- Unity may keep, reuse, or delay releasing resources.
- Monitoring tools use different counting methods.
- Models, shaders, render textures, UI, and audio buffers also use memory.
- Mipmaps, compression format, alpha channels, and actual upload formats affect usage.

Use the estimate to compare trends, such as whether scaling should reduce VRAM. Do not expect it to match Task Manager exactly.

## Recommended Setups

### Safe Optimization

- Output: DDS.
- Scale: no scaling.
- Mipmaps: on.

Good when you do not want quality loss and only want textures to be easier for the game to read.

### Large Mod List, Balanced Quality And Performance

- Output: DDS.
- Scale: 50% or 60%.
- Minimum clarity: 128.
- Mipmaps: on.

This fits most large mod setups better.

### Very Tight VRAM

- Output: DDS.
- Scale: 40%, 25%, or 20%.
- Minimum clarity: 128 or higher.

This saves more resources but has obvious quality risk. Back up or test on a smaller range first.

### Tight Disk Space

- Output: ZSTD.
- Confirm Image Opt is installed and enabled.
- Choose scale based on quality needs.

ZSTD mainly helps disk usage. Do not assume it is always faster.

## FAQ

### Can I Delete PNG After Generating DDS?

Not recommended. PNG is the original texture and is needed for regeneration, rollback, and troubleshooting. Optimized outputs are extra files, not replacements for source management.

### Textures Became Blurry

Increase the scale ratio, such as from 50% to 75% or no scaling, then regenerate with overwrite. You can also increase minimum clarity to protect small images.

### ZSTD Was Generated But The Game Does Not Use It

Check whether Image Opt is installed and enabled. Without Image Opt, DDS.ZSTD may just sit on disk unused.

### Why Are Some Images Not Scaled?

They may be mask textures, outside the processing range, or would fall below minimum clarity after scaling. RimCrow avoids forcing these images.

### When Should I Regenerate?

Use overwrite generation when:

- Output format changed.
- Scale ratio changed.
- Mipmap setting changed.
- Old output statistics clearly do not match the current strategy.

For daily small mod additions, use incremental generation.

## Notes

- First generation may be slow. More textures take longer.
- Close the game before generating to avoid file locks or inconsistent results.
- Start with conservative settings for large mod lists, then lower scale gradually.
- ZSTD needs Image Opt. Older game versions may need Graphics Settings+ for DDS.
- Texture optimization mainly affects texture reading, disk usage, and VRAM. It does not solve every slow loading or stutter problem.
