# 模组列表与加载顺序说明

这份文档说明主界面的 Mod 列表怎么用，以及哪些操作会影响游戏实际加载顺序。

简单理解：

- 停用列表：当前不加载，但仍然保留在普通 Mod 库里的 Mod。
- 启用列表：游戏实际加载读取的 Mod 顺序。
- 临时列表：只在管理器里临时整理用，与游戏无关，可视为停用列表。
- 禁用列表：被明确禁止进入游戏的 Mod，游戏里一般看不到。
- 保存：把当前启用顺序写入对应环境的游戏配置。

## 列表里的 Mod 从哪里来

RimCrow 扫描后会把不同来源的 Mod 放到同一套管理视图里。常见来源包括：

- 本地 Mod：游戏本体 `Mods` 目录里的 Mod。
- Steam 工坊 Mod：Steam 工坊目录里的 Mod。
- 管理器模组：RimCrow 通过 SteamCMD、Git 或直链等方式下载的 Mod。
- 官方内容：游戏本体和 DLC。

不同来源会影响部署方式、更新方式和删除方式。不要只看 Mod 名称，遇到重复或共存时要先看来源。

## 四类列表怎么理解

### 停用列表

这里放的是当前环境没有启用的 Mod。它们仍然存在于你的磁盘、工坊库或管理器库里，只是当前加载顺序没有使用。

适合：

- 暂时不用的 Mod。
- 等待测试的 Mod。
- 有冲突但暂时不想删除的 Mod。

注意：

- 停用不等于删除文件。
- 停用的 Mod 仍可能在管理器里被搜索、分组、打标签或再次启用。
- 如果只是今天不用，放停用列表通常比禁用更合适。

### 启用列表

这里就是当前环境的实际加载顺序。越靠上越早加载，越靠下越晚加载。

常见情况：

- 前置库、框架、官方内容通常靠前。
- 普通内容 Mod 居中。
- 补丁、语言包、性能优化、末端修复通常靠后。

具体顺序仍以 Mod 说明、规则提示和实际测试为准。

### 临时列表

临时列表在右侧辅助栏里。它像一个“暂存区”，用于临时放一批你正在整理、测试或准备批量移动的 Mod。

适合：

- 从停用列表里先挑出一批候选 Mod。
- 导入列表后临时观察，不马上写进启用列表。
- 做一轮测试前，把待处理 Mod 单独放一边。
- 整理大型列表时，先把一类 Mod 暂时集中起来。

注意：

- 临时列表里的 Mod 不会进入游戏加载顺序，效果更接近停用。
- 临时列表主要是管理器里的整理状态，不要把它当成备份。
- 设置里有“保存临时列表”：开启后会按当前环境恢复；关闭后，保存时会把临时列表里的 Mod 放回停用列表顶部。
- 如果要长期保存一批 Mod 组合，优先使用分组或备份，不要只依赖临时列表。

### 禁用列表

禁用列表在右侧辅助栏的“已禁用”页。这里放的是你明确不希望游戏读取的 Mod。

适合：

- 已确认会造成冲突，暂时不想让游戏看到的 Mod。
- 多个副本里不想参与当前环境的一份。
- 从冲突处理或库存管理中标记为禁用的 Mod。
- 需要严格控制整合包可见范围的场景。

注意：

- 禁用比停用更强。停用只是“不加载”，禁用是“尽量不让游戏看到它”。
- 已禁用 Mod 可以在禁用列表中筛选、排序、右键解除禁用。
- 禁用列表里的删除、取消订阅会影响真实来源，操作前先确认路径和来源。
- 开启严格禁用模式后，扫描时会按管理器记录保持禁用状态；如果外部把它恢复了，RimCrow 会尝试重新禁用。
- 如果只是测试暂时不用，先放停用或临时列表；只有明确不想让它进入环境时再禁用。

## 常用操作

### 启用和停用

- 双击 Mod 可以快速启用或停用。
- 也可以拖拽到另一侧列表。
- 多选后可批量启用或停用。

启用只是把 Mod 加入当前环境的加载列表，不等于复制文件。停用也不会自动删除 Mod 文件。

### 双击

双击是最快的启停方式：

- 在停用列表双击：加入启用列表。
- 在启用列表双击：移回停用列表。

双击后，管理器会在当前排序规则允许范围内尽量找最合理的位置插入 Mod。
另外注意：启用列表变动后及时保存，游戏里才会读取新的启用顺序。

### 拖拽排序

在已启用列表中拖拽可以调整加载顺序。拖拽后的变化需要保存才会写入配置。

如果你手动调整了顺序，建议再看一次问题提示，避免把依赖项拖到错误位置。

在筛选或视图排序状态下，列表只是在“视觉检阅”。这时通常不能拖拽插入或调整真实顺序，但是可以多选拖出到其它列表。想改实际顺序，可以先将目标 Mod 拖入临时列表，然后清掉筛选和视图排序，再拖回原列表或其它位置。

### 多选

常用选择方式：

- 单击：选中一个 Mod。
- `Ctrl` + 单击：追加选择或取消选择一个 Mod。
- `Shift` + 单击：从上一次选中的位置到这次点击的位置连续选择。
- `Ctrl` + `Shift` + 单击：在保留已有选择的基础上追加一段连续范围。
- `Ctrl+A`：全选当前可见列表或筛选结果。

批量操作前，先确认当前筛选条件。否则你可能只操作了筛选结果，而不是完整列表。

#### 扩选（划动框选）

列表左侧的序号列或选择触发区支持划动扩选。按住左键从一个 Mod 划到另一个 Mod，会把中间这一段一起选中。

常见用法：

- 选中一段连续 Mod 后批量启用、停用、移动或打标签。
- 在大列表中比一个个 `Ctrl` 点击更快。
- 配合筛选先缩小范围，再划动扩选。

注意：

- 划动扩选按当前可见顺序计算。
- 按住 `Ctrl` 再划动，会在原有选择基础上追加这一段。
- 如果你开始拖动 Mod 卡片本身，可能会进入拖拽排序；想扩选时尽量从序号列或选择触发区开始。

### 多选次序问题

创建联锁、批量移动这类操作，会参考当前选中项的顺序。不同选择方式的“顺序来源”不一样。

扩选和连选最直观：

- 扩选：也就是划动框选，按当前列表显示顺序选中一段。
- 连选：也就是 `Shift` + 单击，同样按当前列表显示顺序选中一段。

所以用扩选或连选创建联锁时，联锁顺序通常就是你屏幕上看到的上下顺序。即使当前开着筛选或问题过滤，也会按过滤后的可见顺序计算。

`Ctrl` 多选不一样。它是一个个点出来的，点击位置可能前后跳动，所以顺序主要按你的点击次序确定。比如先点第 20 个，再点第 5 个，再点第 12 个，创建联锁时就可能看起来“不按列表上下顺序”。这不是随机，而是因为这次多选本身没有连续范围。

如果你要创建联锁，推荐这样做：

- 一段连续的 Mod：优先用扩选或 `Shift` 连选。
- 分散的 Mod：可以用 `Ctrl` 多选，但创建前最好确认选中顺序。
- 发现联锁顺序不符合预期：解除联锁后，按列表显示顺序重新扩选或连选，再创建联锁。

### 右键菜单

右键菜单适合处理单个或多个 Mod 的常见动作，例如：

- 打开 Mod 路径。
- 打开工坊页面。
- 编辑别名、标签、备注。
- 处理启用、停用、删除、订阅等动作。
- 进入规则编辑或来源处理。

带删除含义的操作要先确认来源。删除本地文件、删除工坊文件、取消订阅不是同一个动作。

### 联锁功能

联锁用于把几项必须相邻的 Mod 绑成一组。创建联锁后，选中其中一个成员时，RimCrow 会自动把同一联锁组里的成员一起带上；拖拽或移动时，也会尽量保持这一组的相对顺序。

适合：

- 主 Mod 和专用补丁必须紧贴。
- 一组框架、扩展、兼容补丁需要成套移动。
- 你不想每次手动排序都重新找它们。

常见操作：

- 多选几个 Mod 后，右键创建联锁。
- 选中已有联锁成员后，右键解除联锁。
- 出现“联锁模组缺失”或“联锁排序错误”时，按提示补齐、下载、订阅、剔除失效项或重新排序。

注意：

- 联锁不是依赖规则。它只表达“这几项最好成组相邻”，不能替代前置依赖或兼容性判断。
- 不要把太多无关 Mod 联锁在一起，否则后续排序和移动会变笨重。
- 自动排序仍会参考依赖、规则和权重；联锁只是其中一个约束。

## 搜索和筛选

主列表有两个输入框，作用不同：

- 上方“搜索定位”：不改变列表内容，只在当前列表中跳到匹配项。左键定位下一个，右键定位上一个。
- 下方“筛选”：缩小当前显示范围，只显示符合条件的 Mod。

筛选后注意看列表数量。很多“找不到 Mod”的情况，其实是筛选条件还开着。

### 基础写法

常见写法：

- 直接输入关键词：按默认字段模糊搜索。
- `类别:关键词`：只在指定字段里搜索。
- `-类别:关键词`：排除匹配这个字段的 Mod。
- `类别:+` / `类别:-` / `类别:_`：用于判断字段是否有值、无值、未知。
- 多个条件可以选择“与”或“或”逻辑。

默认直接搜索会匹配名称、别名和作者。包名、工坊 ID、标签、来源等需要用字段搜索更准确。

输入时可以用 `Tab` 应用建议。空输入时，建议列表会显示可用字段。

### 与 / 或 逻辑

多个搜索条件可以选择关系：

| 逻辑 | 含义 | 例子 |
| --- | --- | --- |
| 与 | 每个条件都满足才显示 | `tags:性能` + `source:workshop` |
| 或 | 满足任意条件就显示 | `tags:性能` + `tags:UI` |

排查问题时通常用“与”，找同类 Mod 时常用“或”。

### 常用字段

这些字段适合在主列表里使用：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `name` | Mod 名称 | `name:Harmony` |
| `alias_name` | 自定义别名 | `alias_name:核心` |
| `author` | 作者 | `author:Oskar` |
| `package_id` | 包名 | `package_id:ludeon` |
| `workshop_id` | 工坊 ID | `workshop_id:2009463077` |
| `tags` | 标签 | `tags:性能` |
| `groups` | 分组 | `groups:中世纪` |
| `sign_color` | 颜色标记 | `sign_color:red` |
| `mod_type` | 类型 | `mod_type:语言包` |
| `source` | 来源 | `source:workshop` |
| `store` | 存放位置 | `store:self` |
| `supported_versions` | 支持版本 | `supported_versions:1.6` |
| `supported_languages` | 支持语言 | `supported_languages:zh` |
| `multiplayer_compat` | 联机兼容性 | `multiplayer_compat:compatible` |
| `ignored_issues` | 已忽略的问题 | `ignored_issues:缺少依赖` |

字段名输入不完整时，可以看输入建议。部分字段也会自动生成较短别名，实际以输入框建议为准。

### 判断类字段

判断类字段适合查“有没有某种状态”：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `last_active` | 最近是否启用过 | `last_active:+` |
| `coexist_variant` | 是否存在共存版本 | `coexist_variant:+` |
| `shadow_paths` | 是否存在禁用副本 | `shadow_paths:+` |
| `replacement` | 是否存在替代项 | `replacement:+` |
| `save_breaking` | 是否标记为坏档风险 | `save_breaking:+` |

三种值的含义：

- `+`：有值 / 是。
- `-`：无值 / 否。
- `_`：未知 / 空。

例如：

- `replacement:+`：只看存在替代项的 Mod。
- `save_breaking:+`：只看有坏档风险提示的 Mod。
- `coexist_variant:-`：只看没有共存版本的 Mod。

### 排除搜索

在字段前加 `-` 表示排除。

例子：

- `-tags:测试`：隐藏带“测试”标签的 Mod。
- `-source:workshop`：隐藏工坊来源。
- `-author:unknown`：排除作者里包含 unknown 的项。

排除搜索也可以和其它条件一起用。例如：`tags:性能` + `-source:local`，表示只看带“性能”标签、但不是本地来源的 Mod。

### 搜索和排序的注意事项

- 筛选和排序主要用于查看，不代表真实加载顺序已经改变。
- 筛选或排序开启时，通常不能拖拽改变实际顺序。
- 清掉筛选、恢复默认排序后，看到的才是当前列表的真实顺序。
- 搜索定位不会改变列表内容；筛选会改变可见范围。
- `Ctrl+A`、`Shift` 连选和划动扩选都按当前可见列表计算。

### 禁用列表里的搜索

禁用列表使用更简单的搜索框，可按名称、包名、工坊 ID 和路径筛选；旁边还能按来源和时间、体积、名称排序。

禁用列表的排序只用于查看，不表示这些 Mod 会进入加载顺序。

## 分组、标签、颜色和备注

这些功能主要服务于整理，不一定直接改变游戏加载行为。

### 分组

分组像收藏夹或主题包，适合保存一批相关 Mod，例如“中世纪包”“测试包”“常用 UI”。

把分组拖到启用或停用列表，可以做批量启停。分组本身不是游戏加载顺序文件。

### 标签

标签适合给 Mod 打长期标记，例如“性能”“种族”“建筑”“待测试”。后续可以用于搜索、筛选和动态规则。

### 颜色

颜色适合快速识别重点 Mod，比如核心框架、问题 Mod、自己常改的 Mod。

### 备注

备注适合记录你自己的判断，例如“这个版本别更新”“需要排在某某之后”“多人联机暂不启用”。

## 问题提示怎么看

列表里的问题提示来自依赖、排序、兼容性、文件缺失、语言包、联锁和联机兼容性检查。它们不是装饰信息，启动前建议至少看一眼启用列表右上角的问题数量。

简单判断：

- 红色错误：优先处理。它很可能影响游戏加载、导致启动失败、进存档报错，或引出更多后续错误。
- 黄色警告：建议确认。一般不会立刻造成严重问题，但可能影响排序、语言显示、联锁完整性或特定玩法。
- 蓝色提示：通常是信息说明，例如依赖已由替代 Mod 满足，主要帮助你理解当前状态。

如果时间有限，先处理红色错误；黄色警告可以根据你是否在意对应功能再决定。

### 从哪里看问题

常见入口：

- 列表右上角的问题数字：显示当前列表里有多少问题。
- Mod 行上的提示图标：鼠标悬停可查看具体原因。
- 问题筛选：点击问题数量可只看有问题的 Mod。
- 右键菜单：可对部分问题执行忽略、恢复警告、补订阅、补下载或联锁修复。

遇到问题很多时，不要从列表第一行硬看。先点问题汇总筛选，再按红色错误优先处理。

### 红色错误

红色错误通常表示当前列表已经明显不满足游戏或规则要求。继续启动有较高概率出问题。

常见原因：

- 本地文件缺失或 Mod 解析失败。
- 缺少必要前置。
- 依赖项没有启用。
- 依赖顺序错误，例如必须在前置之后加载却排错了。
- 存在明确不兼容关系。
- Multiplayer 明确不兼容。

建议处理顺序：

1. 先补齐缺失文件和必要前置。
2. 再启用未启用的依赖。
3. 然后自动排序或手动调整顺序。
4. 最后处理明确不兼容项，通常需要二选一、安装兼容补丁，或确认是否有替代方案。

不要用“忽略”来压掉红色错误。只有你非常确定当前环境不受影响时，才考虑忽略。

### 黄色警告

黄色警告通常表示“可能不理想”或“信息不足”。它一般不会像红色错误那样直接导致游戏启动失败，但仍值得确认。

常见原因：

- 可能缺少推荐前置。
- 语言包指向不明确。
- 当前语言缺少语言包，或语言包对应主 Mod 未启用。
- 排序建议不完全满足。
- Mod 支持版本和当前游戏版本不匹配。
- 联锁组缺成员，或联锁成员没有紧挨着。
- Multiplayer 兼容性较差或未知。
- 来源信息不足，需要人工判断。

建议处理方式：

- 和依赖、排序有关：先自动排序，再看是否还存在。
- 和语言包有关：如果你不需要这个语言，可以暂时不处理；如果要中文或其它语言显示，建议补齐或启用对应语言包。
- 和版本有关：检查 Mod 说明页、更新状态和游戏版本。
- 和联锁有关：把联锁组成员放回相邻位置，或剔除已经失效的联锁项。
- 和联机兼容有关：只有玩 Multiplayer 时才需要重点处理；单机玩家可以按需确认。

黄色警告可以忽略，但建议只忽略你已经理解原因的问题。忽略后它不会继续打扰你，不代表问题被修好了。

### 蓝色提示

蓝色提示通常用于解释当前列表状态，不一定需要操作。

常见情况：

- 某个依赖已由替代 Mod 满足。
- 某些兼容性信息只是提醒你注意。

如果游戏能正常运行，蓝色提示通常可以保留。

### 推荐排查顺序

日常整理列表时，可以按这个顺序来：

1. 扫描，保证列表状态最新。
2. 点击问题汇总，只看有问题的 Mod。
3. 先处理红色错误。
4. 自动排序，再看剩余问题。
5. 处理你在意的黄色警告。
6. 保存前再看一次问题数量。
7. 启动游戏测试。

每次不要同时改太多。尤其是大型列表，最好一次处理一类问题，确认变化后再继续。

### 什么时候可以忽略

适合忽略的情况：

- 你已经看过 Mod 说明，确认这个警告对当前玩法无影响。
- 规则库提示较保守，但你实际测试正常。
- 语言包、联机兼容等提示与你当前需求无关。

不建议忽略的情况：

- 缺少必要前置。
- 依赖没有启用。
- 明确不兼容。
- 文件缺失。
- 启动或进存档已经出现红字、卡加载、坏档等问题。

如果不确定，就先不要忽略。保留提示能帮助后续排查。

## 重复、共存和缺失

### 重复包名

多个来源出现相同 PackageId 时，RimCrow 会识别出重复或共存状态。不要只按名称判断，因为不同文件夹可能是同一个 Mod 的不同副本。

### 共存版本

有时你会同时拥有本地版和工坊版。RimCrow 会尽量显示来源差异，并在运行时选择更合适的一份。

需要长期保留多个版本时，建议做好备注，避免以后忘记为什么保留。

### 缺失项

缺失项通常来自导入列表、旧备份或别人分享的加载顺序。它表示列表里有这个包名，但当前环境没有找到对应 Mod 文件。

可以尝试补订阅、补下载，或手动移除缺失项。

## 保存和备份

列表变化不会自动写入游戏配置。你需要点击保存。

保存前建议：

- 处理红色错误。
- 确认当前环境正确。
- 对重要列表保留备份。
- 如果刚导入外部列表，先看差异再加载。

更多说明见 [备份与导入导出说明](./备份与导入导出说明.md)。

## 常见问题

### 我停用了 Mod，文件会被删吗？

不会。停用只是从当前环境加载顺序里移除，不等于删除文件或取消订阅。

### 拖拽后为什么游戏里没变？

需要保存。拖拽和自动排序只是界面里的变更，保存后才写入加载顺序文件。

### 为什么同一个 Mod 出现多个版本？

通常是本地、工坊、管理器库里有多个副本。先看来源，再决定保留、禁用、删除或转本地。

### 为什么自动排序后还有问题？

自动排序依赖已有规则和可识别的 Mod 信息。没有规则、规则冲突或 Mod 信息不足时，仍需要你手动判断。
